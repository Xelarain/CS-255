# CS-255
DriverPass Project Summary
The client for this project was DriverPass, a driving school owned by Liam, alongside his IT Officer, Ian. They needed a comprehensive, cloud-hosted system to manage their day-to-day operations. The designed system automates online scheduling for two-hour driving lessons, integrates with the DMV system for policy updates, tracks user activity for offline reporting, and enforces Role-Based Access Control (RBAC) to ensure security across various user types (staff, students, and instructors).

Strengths in the Process
I excelled at translating complex technical requirements into accessible visual models. By developing clear UML diagrams—particularly the Use Case and Activity diagrams—I was able to map out exactly how different stakeholders interact with the platform without overwhelming a non-technical audience with database jargon.

Areas for Revision
If I could revise one part of my work, I would refine my initial approach to generating the UML Use Case diagrams. Initially, automated flowchart generators scrambled the relationship lines and dropped key actors like the Driving Instructor. I would improve this by starting with manual, strict UML-compliant mapping from the very beginning to ensure absolute accuracy in the relationships between actors and system boundaries.

Interpreting User Needs
I interpreted the user's needs by analyzing the specific pain points of each stakeholder. For instance, the secretary needed automated scheduling to save time on the phone, while the IT Officer needed centralized security controls. Considering the user's needs is critical because even the most technically advanced software will fail if it does not solve the client's actual day-to-day operational problems or if it disrupts their business workflow.

Software Design Approach
I approach software design using an Agile, user-centric mindset. Before writing any code, I focus heavily on requirement gathering and visual modeling. In the future, I plan to continue utilizing standardized UML diagrams (like Class, Sequence, and Activity diagrams) and prioritizing detailed user stories.
